# Frequently Asked Questions

## Does the repository prove that the tool is integrated into the Climate Data Hub?

No. It demonstrates development, documentation, sharing, and technical integration readiness. Completed Hub integration requires an approved Hub catalogue, Wiki, workflow, service, or application record and evidence that users can access the product through the agreed route.

## Does each workflow count as a separate reported tool?

Normally, no. Historical, projection, VPD, validation, diagnostics, and reporting workflows are modules of one integrated Climate Data Harmonization Agent unless the reporting authority accepts independently packaged and independently shared products.

## Which countries are currently configured?

Ethiopia, Kenya, and Somalia. Ghana, Tanzania, Uganda, or other geographies should not be described as operational until boundaries, source availability, configurations, tests, completed runs, and validation evidence are added.

## Where should I report a problem?

Use GitHub Issues for reproducible bugs or clearly scoped feature requests. Include the command, run ID, expected behaviour, actual behaviour, environment, and a short safe log excerpt.

## Where should I ask a usage or scientific-method question?

Use GitHub Discussions after it is enabled. Discussions are appropriate for questions, ideas, workflow design, scientific assumptions, demonstrations, and stakeholder feedback that is not yet an implementation task.

## Can I redistribute generated climate data?

The software licence does not replace the licences and access conditions of AgERA5, CHIRPS, ISIMIP, or other source datasets. Users must follow each provider's attribution, access, citation, and redistribution requirements.

## Does passing validation make the data decision-ready?

No. Validation supports technical consistency. Domain experts must still assess physical plausibility, uncertainty, model suitability, and the interpretation required for decisions or advisories.
